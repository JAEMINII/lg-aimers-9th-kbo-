# 신경망 실험 인계 문서

더 좋은 CPU(또는 GPU) 에서 이어 돌리기 위한 문서. 다른 에이전트가 이것만 보고 실행할 수 있게 썼다.

---

## 0. 배경 — 지금 어디까지 왔나

야구 제구 성공 예측 대회. 학습 1,475,092행(2019~2024) → 평가 2025.

```
지표   Score = 100000 x (1 − Brier / (r(1−r)))       r ≈ 0.5238
       분모가 0.25 라 평균오차 1%p 가 40점. 매우 민감하다.
```

**리더보드 실적**

| 제출 | 구성 | 점수 |
|---|---|---|
| jaemin_5 | sklearn HistGB 전체단독, shift −0.05 | 964 |
| (재민) | sklearn HistGB 60+40 라우팅, shift 0 | **989** ← 현재 최고 |
| jaemin_8 | CatBoost 60+40, shift −0.05 | 975 |
| jaemin_9 | CatBoost 60+40, shift 0 | 987 |

**확정된 사실**
- 147만 행에서는 **sklearn 과 CatBoost 가 동점**(989 vs 987). GBDT 안에서 알고리즘을 바꿔봐야 얻을 게 없다.
- `0.6 x 전체train + 0.4 x (경기유형별 단독모델)` 라우팅 블렌딩이 964 → 989 를 만들었다.
- 블렌딩이 이미 예측 수준을 보정하므로 **shift 0 이 맞다** (975 → 987, +12).

**신경망을 보는 이유**
TabReD(ICLR 2025)가 "시간 분할 환경에서는 GBDT 우위가 줄고 MLP+수치임베딩이 GBDT 와 동등"이라고 보고한다.
우리 문제가 정확히 시간 분할이다. GBDT 끼리는 예측 상관이 0.982 라 앙상블 이득이 없는데,
FC 는 0.93 이라 **근사 방식이 실제로 다르다.** 다만 아직 약해서 이득이 안 난다.

## 1. 측정 규약 — 반드시 이대로

```
관문      학습 season < 2024  →  검증 season == 2024
채점      1군(game_type == "R") 행만. 2025 평가는 전부 1군이다
보정      shift 0 과 −0.05 를 둘 다 보고
```

**같은 관문에서의 기준값 (1군, shift 0 / −0.05)**

| 모델 | 점수 |
|---|---|
| FC 손구현 3시드 | 752.2 / 785.5 |
| sklearn 전체단독 | 814.2 / 856.2 |
| CatBoost 전체단독 | 844.5 / 876.5 |
| **CatBoost 60+40** | **850.6 / 886.3** ← 넘어야 할 선 |

**판정선**: 신경망이 관문 1군 **850 이상**이면 앙상블 비중이 0.05 → 0.3 대로 올라가 실제 이득이 난다.
현재 FC 최고가 785.5 라 **+65 가 부족**하다.

주의: 관문은 **부호는 맞히지만 크기는 못 맞힌다**(CatBoost 관문 +37 이었는데 리더보드 −2).
그러니 관문값으로 "이롭다/해롭다"만 판정하고, 크기는 리더보드로만 확인한다.

## 4. 실행 순서

### ① 공식 MLP-PLR 전체 데이터 (최우선)

```bash
SUB_N=0 python pytk_run.py
```

`SUB_N=0` 이면 전체 122만 행을 쓴다. 부분표본으로 먼저 시간을 재려면 `SUB_N=200000`.

**측정된 실적 (CPU 4스레드, 20만 행 부분표본, 관문 1군 shift 0 / −0.05)**

| 모델 | 시드 | 시간 | 점수 | 122만 행 추정 시간 |
|---|---|---|---|---|
| **MLP-PLR (TD)** | 1 | 4,055초 (68분) | **602.5 / 607.1** | 약 7시간 |
| RealMLP (TD) | 1 | 5,580초 (93분) | 503.1 / 516.1 | 약 9시간 |
| FC 손구현 | 3 | 약 4분 | 524.0 / 541.0 | (116만 행에서 785.5) |

MLP-PLR 이 RealMLP 보다 91점 높다. 논문대로 수치 임베딩이 일한다.
**RealMLP 는 느리고 낮아서 스크립트에서 뺐다.** 우선순위 낮음.

**MLP-PLR(1시드) 이 FC 손구현(3시드) 보다 66점 높다.** 3분의 1 학습 횟수로 이긴다.
손구현은 단일 시드가 극도로 불안정하다: 20만 행에서 +67.0 / −325.8 / +206.3 (편차 532).
앙상블이 그걸 541 로 끌어올리는데(평균 −17.5 → 541.0, +558), 즉 **개별 모델이 거의 무상관 잡음**이다.
정규화(sigma 미튜닝·분위수변환 누락)와 최적화(OneCycle 8에포크·작은 내부검증 조기종료)가
전부 어긋나 있어서, 데이터가 많아야 겨우 돌아가는 상태였다.

### 전체 데이터 실측 — 붕괴했다 (2026-08-19)

```
MLP-PLR (TD)   20만 행    4,055초    602.5 / 607.1     정상
MLP-PLR (TD)  122만 행    4,720초     15.3 / 197.2     붕괴
```

**데이터가 6배인데 시간은 16%만 늘었다.** 학습 스텝이 데이터에 비례해 늘지 않았다.

진단:
```
1군 예측 평균 0.5143  실제 0.4897     +2.46%p 과대예측
완벽 재중심화 후 BSS = 98.5           판별력 자체가 무너짐
```
수준 문제만이 아니다. 예측 평균을 실제에 맞춰도 98.5 다(CatBoost 886).

**원인: pytabkit 의 TD(tuned defaults) 는 논문 벤치마크에서 잡은 값이고,
그 데이터셋들이 대체로 10만 행 이하다.** 122만 행에서는 에포크·배치·학습률 조합이 안 맞는다.
공식 구현이라고 만능이 아니다 — 내 손구현의 sigma 를 잘못 찍은 것과 종류만 다른 같은 문제다.

### 그래서 GPU 에서 다시 한다면

`SUB_N=0` 을 그냥 돌리면 **똑같이 무너진다.** 반드시 하이퍼파라미터부터 손봐야 한다:

```python
MLP_PLR_D_Classifier(
    n_epochs=...,        # 기본값이 이 규모에 부족. 늘려야 함
    batch_size=...,      # 기본 256 근처. 122만 행이면 1024~4096
    lr=...,              # 배치를 키우면 같이 올려야 함
    random_state=s, n_threads=<코어수>, device="cuda")
```
`MLP_PLR_D_Classifier.__init__` 의 35개 파라미터를 `inspect.signature` 로 확인하면 된다.

**주의: 튜닝하려면 관문(2024)을 반복해서 보게 되는데 그러면 관문이 오염된다.**
`tabm_v2.py` 처럼 2019~2022 → 2023 으로 별도 검증을 만들어 거기서 튜닝하고,
관문은 마지막에 한 번만 봐야 한다.

### 현재 결론 — 이 축은 닫았다

```
MLP 최고        607.1  (20만 행)
CatBoost 60+40  886.3
                −279

앙상블 최적 비중 0.05, 이득 +0.1  (corr_fc.py 실측)
```
FC 예측과 GBDT 예측의 상관은 0.9347 로 **확실히 다른 모델이다**(GBDT 끼리는 0.982).
다양성은 충분한데 **강도가 279 부족해서** 섞으면 끌어내린다.
850 근처까지 올려야 앙상블이 열리는데, 이 계산 자원으로는 경로가 안 보인다.

이래서 더 좋은 CPU 가 필요하다. **GPU 가 있으면 `device="cuda"` 로 바꾸면 훨씬 빠르다**
(`pytk_run.py` 의 `device="cpu"` 부분).

`RealMLP` 는 20만 행 93분에 관문 1군 503.1/516.1 로 느리고 낮아서 스크립트에서 뺐다.
되살리려면 `MODELS` 딕셔너리에 다시 넣으면 된다:
```python
"RealMLP (TD)": lambda s: RealMLP_TD_Classifier(
    random_state=s, n_threads=4, verbosity=0, device="cpu"),
```

## 5. 손구현의 알려진 결함 — 고칠 거면 여기부터

`tabm_plr.py` / `tabm_v2.py` 는 논문 구조의 **근사치**다. 편차가 결과를 좌우할 만하다.

**PLR** (On Embeddings for Numerical Features, NeurIPS 2022)

| 논문 | 손구현 | 영향 |
|---|---|---|
| sigma 를 데이터셋마다 튜닝 (0.01~100) | 0.1 고정, 근거 없음 | **가장 큼.** 논문이 최민감 파라미터로 지목 |
| 입력에 분위수 변환 | 표준화 | 주기함수는 입력 스케일에 직접 반응 → sigma 와 얽힘 |
| d_emb 16~24 | 8 | 중간 |

**TabM** (ICLR 2025)

| 논문 | 손구현 |
|---|---|
| k = 32 헤드 | k = 8 |
| TabM_mini (입력단 어댑터 1개) | 전 층에 r·s·b (BatchEnsemble 원형) |
| MLP 블록에 정규화 없음 | BatchNorm 추가 |
| 상수 lr + patience 16 조기종료 | OneCycle 8에포크 |

**실제로 `tabm_v2.py` 곡선이 무너졌다** (2023 검증 1군): ep01 635 → ep02 748 → ep03 620 → ep04 624 → ep05 453.
OneCycle 최고점 부근의 높은 학습률이 원인으로 보인다. 이건 **방법이 아니라 내 설정을 시험한 것**이다.

## 6. 검증 설계에서 배운 것 — 중요

**연도 간격이 없는 검증은 쓰면 안 된다.**

`fc_proper.py` 의 내부검증(학습구간 마지막 5% = 2023 후반)은 관문과 **정반대로** 움직였다:

```
        내부Brier    관문 1군 (shift −0.05)
ep01    0.248784      770.4      ← 관문 최고
ep03    0.248412      745.2
ep05    0.248320      736.3      ← 내부 최저
```

내부검증으로 에포크를 고르면 관문 최악을 고른다. 같은 이유로:
- 재민님 로컬 ablation(2019~2023+2024앞80% → 2024뒤20%)이 `타자 x 투수손` 피처에 +20.2 를 줬는데 **리더보드는 −1** 이었다.
- 같은 검증이 shift 0 이 최적이라 했는데, 그건 우연히 맞았다(다른 이유로).

**대안**: `tabm_v2.py` 처럼 학습 2019~2022 → 검증 2023 으로 1년 간격을 만든다.

**예측 재중심화도 넣어야 한다.** 신경망은 에포크마다 예측 수준이 요동친다
(v1 에서 shift 0 과 −0.05 의 순서가 ep04↔ep05 에서 뒤집혔고 차이가 109점).
```python
logit(p) - mean(logit(p)) + C      # C = 학습 마지막 시즌 성공률의 로짓
```
`tabm_v2.py` 에 구현돼 있다. 수준 잡음을 없애야 판별력만 남아 비교가 깨끗해진다.

```
관문 1군 850 이상        →  성공. corr_fc.py 로 앙상블 비율 잡고 제출본 빌드
```

(임베딩은 인덱싱, PLR 은 sin/cos, 선형층은 `@`). 트리보다 오히려 쉽다.
